## 端到端复测 + 真正根因（2026-09-07 晚，使用 start-joint-ai.bat 路径）

用户用 `scripts/start-joint-ai.bat` 启动后"视频正常、AI 不显示"。我做了完整 E2E：
1. 启动 video-server（joint 配置 config.joint.yaml，http_port=8081）→ 8081 健康 ✅。
2. **手动传错配置路径** `config.joint.yaml`（缺 `config/` 前缀）→ `Load()` 静默回退默认 8080，是个隐患（路径打错会无声吞掉）。正确路径 `config/config.joint.yaml` 才会监听 8081。
3. 用和脚本一致的参数跑 agent（build-msvc，自报 backend=gstreamer，枚举到真机 "Integrated Camera"），向 8081 推送 → camera01 自动注册、metadata 帧 `sent=173 failed=0` 全成功 ✅。
4. `GET /api/cameras/camera01/metadata` **返回真实检测帧但 frame 里没有 `ai_mode` 字段**（omitzero 省略）。手灌带 `ai_mode:"ai-y"` 的合成帧能正常往返 → 服务端能存/返 ai_mode，**问题在 agent 发出的帧没带 ai_mode**。

### 真正根因：agent 二进制过旧（不是代码 bug）
- `carmera-agent/src/ai/ai_pipeline.cpp`（含 `res.ai_mode = aimode_web_string(current_mode_)` 打标，commit `b2a5e87`）mtime = **2026-09-04 19:00**。
- `carmera-agent/build-msvc/src/camera-agent.exe`（正在跑的二进制）mtime = **2026-09-03 21:09**，**比源码早约 22 小时** → 二进制没有 ai_mode 打标逻辑。
- agent debug 日志 `grep -c ai_mode` = 0；发出的帧 payload 确实不含 `ai_mode`。
- UI 门控 `VideoPlayer.vue:201-207`：`if (!frameMode || frameMode !== aiMode.value) clearOverlay()` → `frame.ai_mode` 缺失使 `frameMode` 为 undefined → **每帧都被判不匹配 → overlay 永远清空 → 不画任何框**。视频(RTSP)与 metadata 传输都正常 → 完美解释"视频正常、AI 不显示"。

### 修复（本沙箱无 cmake/onnxruntime，无法在此重建；需在用户机执行）
- 重新构建 agent，使二进制包含当前源码（含 ai_mode 打标）：`carmera-agent/build_oneclick.bat`（默认 gstreamer 后端），或 `scripts/build-msvc.ps1 -Backend gstreamer`。
- 重建后 agent 发出的帧带 `ai_mode:"ai-y"`，UI 门控匹配 → 框正常显示。
- 注意：联合脚本优先选 `build-msvc-gst/`，缺失时回退 `build-msvc/`；两者都要是**最新构建**。

### 经验教训
- "视频正常但 AI 不显示" 这类症状，**先查 agent 发出的 metadata payload 是否带 `ai_mode`**（debug + `--metadata-log-payload` 抓 wire JSON），而不是先怀疑端口/服务端。
- 二进制 mtime 与源码 mtime 比对 + `grep` 实际 payload，是判断"代码对但二进制旧"的快准方法。
- `Load()` 配置缺失静默回退默认是隐患：建议改为"文件不存在直接 fatal 退出"或至少 warn 日志，避免路径打错被无声吞掉。
- 我之前那次"端口问题"的修复（metadata.server_url 8000→8080、aimode_base_url 派生）对联合脚本路径无影响（脚本用配置端口覆盖）；它只修复 standalone 路径。真正的 AI 不显示根因是本条目所述旧二进制。
