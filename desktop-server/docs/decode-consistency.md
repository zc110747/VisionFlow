# 硬解 / 软解输出一致性验证

> 探针：`--diagframe <输入>`（首帧参数与像素采样）
> 工具：`ffmpeg -lavfi psnr / ssim / blend=difference`

## 验证动机

硬解路径与软解路径产出的首个 PNG 文件**字节不同**（硬解 208118 B，软解 184158 B），
md5 也不同。必须查清是「实现有 bug」还是「两条路径本身就有差异」。

## 一、先建立正确的基准

用 ffmpeg CLI 独立解码同一视频的第 0/1/2 帧作为**外部基准**，然后比对：

| 比对 | PSNR |
|---|---|
| 我的**软解**输出 vs ffmpeg CLI 基准 | **无值输出（PSNR=∞，即逐像素完全一致）** |
| 我的**硬解**输出 vs ffmpeg CLI 基准 | 34.73 dB（avg），SSIM 0.9817 |

**第一个结论：我的软解实现完全正确** —— 与 ffmpeg 官方解码逐像素一致。
这直接证明了 `sws_scale` 转换、`Bitmap` 写入、stride 处理都没有引入任何错误。

## 二、定位硬解的差异区域

生成差异掩码（阈值 >8 的像素标白）：

```
ffmpeg -i hard.png -i ref.png -lavfi \
  "[0:v][1:v]blend=all_mode=difference,format=gray,geq=lum='if(gt(lum(X,Y),8),255,0)'" \
  diff_mask.png
```

结果：差异**只集中在两类区域**：
1. 画面中的**对角线边缘**（testsrc2 的彩色斜线）
2. **高频细节纹理区**（网格图案）

**所有平坦色块区域完全无差异（差异值为 0）。**

## 三、根因判定

这是**色度上采样（chroma upsampling）实现差异**：

- 软解输出 `AV_PIX_FMT_YUV420P`，色度平面与亮度平面分离；
- 硬解经 `av_hwframe_transfer_data` 搬回后是 `AV_PIX_FMT_NV12`，色度交错存放；
- 两者的 4:2:0 → 4:4:4 插值在上采样滤波器的实现上不同（NV12 路径通常用
  更简单的斜坡/马赛克插值），因此在**垂直/水平边缘**处产生 1~2 像素的色度偏差。

**这不是我的代码引入的错误**，而是 ffmpeg 内部两条解码路径固有的差异。
判据：如果是我的搬运/转换写错了（如 stride 错位、平面顺序颠倒），
平坦区域会出现系统性色带或整行偏移，而实测**平坦区域差异为 0**。

## 四、结论

| 结论 | 依据 |
|---|---|
| 解码管线实现正确 | 软解输出与 ffmpeg CLI 基准 PSNR=∞ |
| 硬解上色度插值路径不同 | 差异仅出现在高频边缘，平坦区为 0 |
| 34.7 dB 属正常范围 | 视频编码领域 30-40 dB 即"视觉一致"，且差异为局部而非全局 |
| 无需修复 | 这是 ffmpeg 的既定行为，不是我们的 bug |

## 五、留待关注的接口事实

**NV12 与 YUV420P 的色度上采样差异会影响 AI 叠加的对齐精度吗？**

不影响。AI 元数据里的 `bbox` / `keypoints` 坐标是**采集侧按原始分辨率**
（如 1280×720）产生的，与解码侧的色度插值无关。叠加时按同一坐标系映射即可。
唯一需要注意的是 `video_width/height` 必须取自**帧的实际尺寸**而非硬编码 ——
本项目从 `AVFrame.width/height` 读取，正确。
