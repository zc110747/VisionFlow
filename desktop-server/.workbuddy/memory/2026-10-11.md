# 2026-10-11（续）— 修复「打开本地摄像头显示线程异常」

## 现象
用户报告：打开本地摄像头时抛出「显示线程异常」。

## 根因（代码审查定位）
`CameraPreviewController` 与 `PlayerController` 的后台工作线程在
`CaptureLoop/DecodeLoop` 的 `finally` 中（以及设备异常结束时）触发
`RunningChanged` / `Ended` 事件；其处理器 `OnCameraRunningChanged`、
摄像头 `Ended` lambda、以及 `OnPlayerPlayingChanged` **直接访问 WinForms 控件**
（`_playPauseButton.Text`、`_stopButton.Enabled`、`MessageBox.Show(this,…)`），
而这些事件是在**工作线程**上触发的 → 抛 `InvalidOperationException`（跨线程操作无效）。
典型触发链：打开摄像头→正常出帧→点停止（或设备异常结束）→`Stop()` 在 UI 线程 `Join` 工作线程，
工作线程 `finally` 触发 `RunningChanged(false)` 于工作线程→跨线程异常。

## 修复（`src/VisionFlow.Desktop/UI/MainForm.cs`）
为三个跨线程事件处理器补 UI 线程封送（与既有 AiMetadataPoller 的 `BeginInvoke` 写法一致）：
- `OnCameraRunningChanged` / `OnPlayerPlayingChanged`：入口 `if (!IsDisposed && InvokeRequired) BeginInvoke(...)`。
- 摄像头 `Ended` lambda 改为具名方法 `OnCameraEnded`，同样 `BeginInvoke` 回 UI 线程后再 `MessageBox.Show`。
- 用 `BeginInvoke`（异步）而非 `Invoke`（同步），避免工作线程与 `Stop()` 的 `Join` 互相死锁。
- `IsDisposed` 前置守卫，避免窗体已释放后 `BeginInvoke` 再抛异常（否则会成为新的工作线程异常）。

## 验证
- `dotnet build -c Debug / -c Release` 均 **0 警告 0 错误**。
- 本机有真实摄像头 `Integrated Camera`：`--camtest 0 --frames 10` 走高级视频处理路径，
  1280x720 RGB32 @30fps，抓 10 帧（6 帧画面变化）`verdict=PASS` → 采集层本身无异常，
  印证原故障确在 UI 事件封送而非采集路径。
- GUI 实际「打开摄像头→停止」的视觉确认建议由用户在真实 GUI 环境做（沙箱无法驱动 WinForms 窗口）。

## InvalidCastException 根因定位与修复（第二轮）

用户复现「打开本地摄像头」仍弹窗：`InvalidCastException … IMFSourceReader … E_NOINTERFACE`。
- **根因**：COM apartment 违规——旧 `CameraPreviewController.Start` 在 UI 线程（STA）执行
  `CameraEnumerator.Open`（建 SourceReader），采集工作线程（MTA）调 `ReadSample`。
  SourceReader/Video Processor MFT 链非完全 agile，跨 apartment 首次 QI 即失败。
  旁证：`--camtest`（同线程）一直 PASS；GUI/`--threadtest`（跨线程）必挂。
- **修复**：`Playback/CameraPreviewController.cs` 重构——`Start` 只拉线程，MF 整个生命周期
  （打开→读帧→释放）收进采集工作线程（MTA，MF 官方推荐 apartment）；
  `RunningChanged(true)` 改为打开成功后由工作线程触发（此时 `Capture` 就绪）；
  `Stop` 不再跨线程 Dispose（顺带消灭「Start→Stop 快速收尾偶发 InvalidCastException」）；
  CaptureLoop catch 输出堆栈。`MainForm.StartCamera` 异步化（"摄像头打开中…"，
  事件回填格式）；附带修 `TryAutoSelect` 同索引不触发 SelectedIndexChanged 的取证缺陷。
- **回归守卫**：`--threadtest` 新增 `phaseA_frames>0` 断言（工作线程实际读帧）。
- **验收**：threadtest pass=7 fail=0（frames=35）；camtest 30 帧 PASS；
  GUI 无人值守（--select-source Integrated + --guicapture）画面正常无弹窗
  （截图 `.workbuddy/gui_camera_fix2.png`）；Debug/Release 双构 0 警告。
