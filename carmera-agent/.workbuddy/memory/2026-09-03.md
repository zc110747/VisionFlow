## WebRTC 重启瞬间一次性 502（Bad Gateway）排查与加固
- 现象：web 端偶发 `502 (Bad Gateway)` 一次，随后正常。
- 根因：502 来自服务端代理上游 MediaMTX。`internal/api/handlers.go:262` 的 `cameraWebRTC`（POST `/api/cameras/{id}/webrtc`）把 SDP offer 经 `Manager.WebRTCOffer` 代理到 MediaMTX WHEP 端点(`webrtcBase/<path>/whep`)；上游瞬时不可达时 `httpClient.Do` 返回 err → handler 回 502。而 `Manager.Start` 只等 MediaMTX **控制 API** 就绪(`waitReady` 12s)，WHEP 端点(`:8889`) 常在控制 API 就绪后再晚几百 ms 才监听。刚重启后浏览器首个 offer 命中未监听端口→连接拒绝→502；客户端 `player.ts` catch 后 `onWebRTCFailure` 重连自愈，故"一次后正常"。HLS 代理(`internal/api/hls.go:47/56`) 同理但 web 实时播放已不用 HLS，未动。
- 修法：`WebRTCOffer` 对 **transport 层错误(err!=nil)** 做 4 次 / 250ms 退避重试，吸收 WHEP 启动竞态；逻辑错误(4xx/5xx)仍立即返回不重试。位于 `internal/mediamtx/manager.go`。
- 验证：`go build -trimpath -o video-server.exe ./cmd/video-server` 通过（新二进制 22:35）。提交 `bd73519`（本地，未推送）。仍须重启运行中的 video-server 才生效。
